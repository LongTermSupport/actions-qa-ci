# actions-qa-ci

actions-qa-ci is the [Defence Before Fix](https://defence-before-fix.github.io/) toolchain for
GitHub Actions code. It is a Go program, `actions-qa`, built as one static binary that bundles
its rule backends. This file holds the binding floor; the depth is one link away.

## Binding floor

- **Defence Before Fix**: found a defect? Do not fix it yet; build the detector for its class
  first. A new check is a defence: a stable identifier, a page stating the correct construction,
  an entry in the identifier index (`docs/rules/README.md`, generated) and a place in
  `actions-qa rules` (the registry in `internal/catalogue`). A suppression, a baseline or a
  narrowing is an Owner decision, never a silent edit; a gap found is closed, not accepted.
- **Test first**: a failing test, or a committed detector, comes before the code that satisfies
  it. A test never discards an error with the blank identifier; it reads or asserts every value
  it receives.
- **No hidden failures**: an error is returned or reported by name, never swallowed. A tool
  that fails is exit 3, an analysis with no verdict is exit 4, and neither is ever reported as
  clean. (Exit 3 is used today for a failing rule or lane, a missing page or unwritable output;
  exit 4 for a file in the default set that cannot be read as a plain file, and for a lane
  process that crashed, was killed, wrote too much or ran past its time limit.)
- **One owner per hazard class**: a hazard is reported by exactly one rule. A bundled backend's
  finding is renamed to this project's stable identifier, and a duplicate is dropped.
- **Conformance is declared, not claimed**: `dbf.json` states the method and toolchain versions
  this repository is audited against and every known gap. The version test pins them; moving
  either is a deliberate change made after the specification itself moves.
- **Releases come from the changelog**: never choose a version or cut a tag by hand. A change a
  consumer can notice carries an `## Unreleased` entry in `CHANGELOG.md`.
- **The repository passes its own checks**: every workflow has `permissions: {}` at the top
  with per-job grants, `concurrency` with cancel-in-progress, `uses:` pinned to a full commit
  SHA, and `persist-credentials: false` on checkout.
- **Public by default**: this repository is public. No secret, credential, internal host or
  private path belongs in a file, a commit message or an issue.

## Working

```bash
gofmt -l .        # prints nothing when formatted
go vet ./...
go test ./...
```

The list of active defences at the end of this file is generated; after a rule is added, removed
or reworded, regenerate it with `go run ./cmd/actions-qa rules --write-agent-summary CLAUDE.md`
(`actionsqaci.agentSummaryCurrent` fails the self-check until you do), as the identifier index
`docs/rules/README.md` is regenerated by its test.

The check that gates a merge is the `CI` job of `.github/workflows/ci.yml`; making it a required
status check through branch protection is the Owner's setting, and is not yet in place. Open a pull request from a
branch named `feature/…`, `bugfix/…` or `chore/…`; the default branch is `main`.

## Where to look

- Layout: `cmd/actions-qa` is the entry point and holds no logic; `internal/cli` is the command
  line; the root package holds what the module declares about itself.
- Pinned third-party binaries: `internal/toolchain/manifest.json` pins each release by archive and
  binary sha256, the runtime refuses a binary that differs, and `go run ./cmd/actions-qa-dev
  fetch bin` downloads the pinned ones for development. An archive is a gzipped tar or a zip (a
  Python wheel); `internal/toolchain` tells them apart by their first bytes.
- The `check` run: `internal/check` discovers the default file set and runs the lanes, which
  `internal/catalogue` lists; `internal/cli/check.go` is the command. A lane marked `Isolated`
  runs in a child process (`internal/check/isolate.go`, started through the hidden `lane`
  command in `internal/cli/lane.go`), so a backend that crashes or hangs is exit 4, not a dead
  program.
- Exceptions: `internal/locate` finds the job and step of a line, `internal/exceptions` applies
  the record's exceptions to findings and reports the stale ones.
- The project record: `internal/record` loads `.github/actions-qa-ci.yml` and judges
  justifications; `internal/firstparty` holds the checks this toolchain makes itself.
- Tracked files and patterns: `internal/gitindex` lists the files the repository tracks by reading
  its index (no `git` is run), and `internal/glob` is the small pattern language the record uses.
  A lane marked `Subject` is about the project, not one file, and runs once per whole-project run.
  `internal/scope` resolves the record's `analyse.include` patterns to tracked files, and a lane
  that `Covers` a kind of included file is widened to select them (`check.Widen`).
- The release archive: `internal/bundle` builds the same bytes every time from the program, the
  tools the manifest pins for the platform (each verified against its pin) and a licence file for
  each; `actions-qa-dev bundle` writes it with `checksums.txt` and never replaces a release.
- Tool currency: `internal/bump` moves a pinned tool to its latest release once that release is
  older than the cooldown (72 hours by default), pinning each platform's asset with
  `toolchain.Pin`; `actions-qa-dev tools bump` rewrites the manifest with it and, given
  `--changelog`, records each move under the changelog's Unreleased `### Changed` heading
  (`internal/changelog`; an `Added` entry never spells a tool's version). The compiled-in
  actionlint library moves the same way: `actions-qa-dev modules bump` (`internal/modbump`) reads
  go.mod and the module proxy and says what to move to, once that version is past the cooldown,
  and `update-tools.yml` runs `go get` for it. Only a tool whose
  provenance route is decided there (`routes`: ShellCheck, which upstream does not attest, and
  zizmor, a PyPI wheel whose download must match the sha256 PyPI publishes for it, taken from
  PyPI's JSON in `internal/bump/pypi.go`) is bumped; any other is refused by name.
- The installer: `internal/installscript/install.sh` is the POSIX sh template of a release's
  `install.sh`, tested by running it with `sh` against real bundles; `actions-qa-dev
  install-script` fills the version and the checksums from `checksums.txt` into it and refuses
  a set of checksums that could not verify both platforms.
- The only code that reaches the network is `internal/branchprotection`, and only under `check
  --online`: it reads the required status checks of a branch from the GitHub API, sends the token
  nowhere but the given https address, follows no redirect and never prints the token.
- The active defences as an agent reads them: `internal/listing` lists them (what `rules` prints)
  and `internal/agentsummary` renders and splices the generated region of `CLAUDE.md` or
  `AGENTS.md`.
- Exit codes: [README.md](README.md#exit-codes).
- Conformance: `dbf.json`, printed by `actions-qa version --json`.

## actions-qa-ci — Active defences

Generated from this project's active configuration by `actions-qa rules --write-agent-summary`; do not
edit. Each line is a standing rule `actions-qa check` enforces; `actions-qa rule-doc <identifier>` prints
its page offline.

- `actionsqaci.actionlint.action` — uses: names a well-formed action reference with a version and valid inputs
- `actionsqaci.actionlint.credentials` — Container and service credentials come from secrets, never as literals
- `actionsqaci.actionlint.deprecated-commands` — No set-output, save-state, set-env or add-path workflow command
- `actionsqaci.actionlint.env-var` — Environment variable names contain no space, = or &
- `actionsqaci.actionlint.events` — on: names real webhook events with valid event configuration
- `actionsqaci.actionlint.expression` — Every ${{ }} expression parses and type-checks, and none puts untrusted input into a script
- `actionsqaci.actionlint.glob` — Branch, tag and path filters are valid glob patterns
- `actionsqaci.actionlint.id` — Job and step IDs are unique and well formed
- `actionsqaci.actionlint.if-cond` — An if: condition is not always true or always false
- `actionsqaci.actionlint.job-needs` — needs: names jobs that exist and form no cycle
- `actionsqaci.actionlint.matrix` — A matrix has no duplicate values and no combination that matches nothing
- `actionsqaci.actionlint.permissions` — permissions: uses real scopes with read, write or none
- `actionsqaci.actionlint.runner-label` — runs-on names a runner label that exists
- `actionsqaci.actionlint.shell-name` — A step's shell is one GitHub provides
- `actionsqaci.actionlint.syntax-check` — A workflow file is valid GitHub Actions workflow syntax
- `actionsqaci.actionlint.workflow-call` — A reusable-workflow call passes the inputs and secrets the callee declares
- `actionsqaci.agentSummaryCurrent` — The generated region of CLAUDE.md or AGENTS.md lists the defences this build has and what the project record narrows
- `actionsqaci.inlineSuppression` — No comment tells zizmor, ratchet or ShellCheck to leave a finding out
- `actionsqaci.lintCoverage` — Every git-tracked file that is workflow-shaped or action-shaped is analysed, or declared unanalysed with a justification
- `actionsqaci.nativeSuppressionConfig` — No tool's own configuration file suppresses a finding: zizmor's file, an actionlint ignore, a pinact ignore_actions
- `actionsqaci.requiredChecks` — Every status check the project record requires is the name of a job in a workflow triggered on pull_request
- `actionsqaci.shellcheck.SC<nnnn>` — Shell in a run: step has no ShellCheck error or warning
- `actionsqaci.staleException` — Every exception in the project record matches a finding in a full run
- `actionsqaci.templateDrift` — Each declared copy of a template is byte-identical to its source, and a missing source or copy is a finding
- `actionsqaci.unjustifiedException` — Every exception in the project record states a hazard, a scope and a decision, and every unanalysed file a hazard and a scope, none of them generic
